# 03 · Problem Solving

**Why this matters:**  
Engineering is largely the skill of solving novel problems under constraints. This skill can be trained deliberately.

---

## Learning Outcomes

- Break down ambiguous problems into clear sub-problems
- Use structured frameworks instead of random trial-and-error
- Debug systematically
- Communicate problem understanding clearly

---

## A Practical Framework

### 1. Understand
- What is the actual problem? (not the symptom)
- What are the constraints?
- What does success look like?
- What are the assumptions?

### 2. Explore
- What similar problems have I seen?
- What are possible approaches?
- What are the trade-offs of each?

### 3. Plan
- Choose an approach
- Break it into steps
- Identify risks and unknowns early

### 4. Execute
- Implement in small, verifiable steps
- Test continuously
- Keep the system in a working state

### 5. Review
- Did it solve the real problem?
- What did I learn?
- How would I do it better next time?

---

## Debugging as Problem Solving

When something is broken:

1. Reproduce reliably
2. Form a hypothesis
3. Test the hypothesis with the smallest possible experiment
4. Narrow the search space
5. Fix and verify
6. Write down the root cause

Never change multiple things at once while debugging.

---

## Exercises

1. Take a hard problem you recently struggled with. Rewrite the process using the framework above.
2. Practice "rubber ducking": explain a current problem out loud (or in writing) as if teaching someone else.
3. Create a personal debugging checklist you will actually use.
