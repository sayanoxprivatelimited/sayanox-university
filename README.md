# Sayanox University

> A free, self-paced introduction to programming and computer science.

Most learning resources are either too academic (theory without practice) or too scattered (random tutorials).  
**Sayanox University** is an introductory learning resource with short lessons and self-guided practice. The broader curriculum is a roadmap, not a complete set of courses.

---

## Vision

Build the kind of knowledge that lasts:

- Strong fundamentals
- Real-world engineering judgment
- Ability to design, debug, and ship systems
- Continuous improvement through deliberate practice

This is not a tutorial dump. It is a **curriculum**.

## How This University Works

The following is a proposed structure for future topics (not all directories exist yet):

```
Topic/
├── README.md          # Why this topic matters + learning outcomes
├── notes/             # Clear, dense explanations
├── exercises/         # Progressive practice problems
├── projects/          # Small to medium real projects
└── resources.md       # Curated high-signal resources
```

Principles:

- **Depth over breadth** — better to deeply understand fewer things
- **Practice > passive reading**
- **Build → Break → Fix** cycle
- **Write things down** (notes, decisions, post-mortems)
- Zero fluff

## Website

The English-language learning site is a lightweight static website. It includes
introductory lessons in ten subjects, browser-local progress, and printable
self-reported completion certificates. Certificates are not independently
verified credentials. No account or backend is required; progress is tied to
one browser and may be lost if its site data is cleared.

To run locally, start `python3 -m http.server 4173` in the repository root and
open `http://localhost:4173`. Run the smoke tests with `node tests/smoke.cjs`.
The site needs no build step and can be deployed as static files on Cloudflare
Workers static assets or Vercel. `_headers` configures Cloudflare static asset
responses; `vercel.json` configures Vercel. Cloudflare does **not** apply
`_headers` to responses generated by Worker code: if the Worker handles the
request itself, add equivalent headers there or serve files through its static
assets binding. The runner worker has a separate CSP allowing eval for local
JavaScript execution. The sandboxed preview has its own isolated CSP allowing
a hash-pinned bootstrap and blob scripts only inside an opaque-origin iframe.
The bootstrap is inline so it can run offline in an opaque sandbox; if edited,
update its SHA-256 CSP hash in the preview meta tag and all preview rules in
`_headers` and `vercel.json` (both hosts can serve extensionless HTML URLs).
Its CSP restricts resource loads and form submission; sandboxed code can still navigate its own frame.
Do not use the practice tools to run untrusted code from other users.

After merging, redeploy the latest `main` via the connected host's Git integration
or its normal static-assets deployment process. On Cloudflare confirm the new
version is deployed to the workers.dev site (a merge alone does not guarantee a
redeploy). Check `/` and `/runner-worker.js` with `curl -sI https://YOUR-SITE/`
and `curl -sI https://YOUR-SITE/runner-worker.js`; compare all six security
headers and ensure the worker has its own CSP, not two combined policies. Also
open the site, run Python, SQL, JavaScript and HTML preview examples, print a
certificate, and test the ID format page. Check Vercel headers the same way if
it is deployed there. HTTP headers can only be confirmed on the deployed host.

For a custom domain, edit the HTTPS URL in `site-url.txt` and run
`node scripts/update-site-url.cjs`, then commit the generated canonical and
Open Graph URLs, social card URLs, sitemap and robots file across the public
pages. `manifest.webmanifest` uses relative URLs, so it follows the host without
a domain edit. The generator is a maintenance tool, not a site build step;
automated tests check the URLs stay in sync.

### Search and social sharing

The homepage includes the Google Search Console verification tag provided by
the site owner. Once the latest site is deployed, use the HTML tag method in
Search Console for the correct URL-prefix property and submit `/sitemap.xml`
there. Adding the tag alone does not complete verification or guarantee search
indexing or ranking. Public pages have unique titles, descriptions, canonical
URLs and social cards. The static course-reading page includes Course microdata;
search engines decide whether and how to use it. Certificates remain free,
self-reported keepsakes and are not independently verified or accredited.

### Course classroom and practice

Open a course for its full-screen overview, background, lesson list, practice
studio, progress and certificate. Python and SQL use self-hosted browser runtimes
(Pyodide and sql.js); JavaScript runs in a disposable web worker. A service
worker caches the site and runtimes after an initial successful online visit,
subject to browser support and storage limits.
HTML/CSS and DOM examples use a sandboxed preview. DOM examples support inline
script elements; external scripts, inline event handlers and form submissions
are blocked. Worker runs time out after 45 seconds. Rust, C and Go require an external compiler; Git and AI use a
scratchpad and linked resources. The studio explains these limitations and
does not pretend to execute unsupported languages. Content is introductory,
not a complete professional curriculum, and completion is self-reported.

Each course includes an optional eight-question knowledge check with feedback,
a best score, a focus mode, lesson bookmarks, and private per-lesson notes and
editor drafts. The course dashboard resumes the most recently opened course.
These features use browser-local storage, not accounts or cloud sync; clearing
site data or using another device will remove or hide the saved information.
Resetting a course clears its completion and quiz score but keeps notes, drafts
and bookmarks. Knowledge checks are formative and do not verify certificate
eligibility. Run code with Ctrl+Enter (or Command+Enter on a Mac).

Each course now has a self-guided project brief with milestones, a self-review
rubric and an optional stretch goal. Project checklist progress is stored
locally and is not automatically graded or submitted. The course catalog also
has versioned JSON export and import controls for Sayanox learning data. The
backup contains notes and code in **plain text**; keep it private. Import
validates the file and replaces this site's existing learning data only after
confirmation. Backups are not cloud sync and certificates are not verified.

### Offline use and accessibility

Open the site online once over HTTPS (or localhost) and wait for the service
worker to finish caching before going offline. Browser storage can be denied or
evicted, so offline availability is not guaranteed. External documentation and
playgrounds still require internet access. Pyodide 0.27.7 and sql.js 1.10.3
are vendored under `vendor/` with their own license files; the site has no build
step. Bump the cache version in `sw.js` when changing cached assets.

The classroom offers keyboard navigation, native modal focus containment, a
reduced-motion mode, focus indicators, and responsive layouts. Use Ctrl/⌘+Enter
to run runnable code. The Python and JavaScript example code challenges use
public, local checks only, not secure evaluation. The suggested learning path
is available at `roadmap/`.

### Learning tools and future platform

Use **Search all lessons** to find published lesson text, examples and practice
prompts. Personal notes are not indexed. Lessons show an approximate time and
beginner label, a reading progress indicator, an example copy button, and a
Markdown download containing the lesson and your personal notes. Downloads are
plain text; keep them private. Completion is confirmed and remains self-reported.
Python and JavaScript challenges provide public hints and example solutions after
an attempt in the current page session; they are not hidden tests or secure assessments. The roadmap page
suggests web, backend, systems and AI paths using existing introductory courses.

The planned move toward an optional Cloudflare backend and the larger feature
list are described in [`docs/platform-roadmap.md`](docs/platform-roadmap.md).
Those features, including accounts, cloud sync and platform-issued certificate
lookup, are not implemented yet. The current site remains static and guest-only.

### Local records and privacy

Certificate IDs are generated with secure random bytes. `verify/` checks only
the ID format; it cannot tell whether an ID was issued. Anyone can create or
edit certificates and local records. This is **not independent verification**,
identity proof, or accreditation. Study streaks, daily goals
and estimated visible-tab course time are also stored locally. The estimate
may include idle time. No data is synced to a server. Backups are unencrypted.
