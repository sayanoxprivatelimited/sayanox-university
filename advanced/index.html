PATH 01 · INTERMEDIATE

Python Intermediate & Advanced

Before you start: Python basics: variables, loops and functions.

Practice setup: Use Python 3.11+ in a local virtual environment. Examples are independent files.

8 lessons
01Classes and instances

Understand

A class defines behavior and an instance holds its own state. Methods receive the instance as self; initializing a new object calls __init__.

Example

class StudySession:
    def __init__(self, topic, minutes):
        self.topic = topic
        self.minutes = minutes

    def describe(self):
        return f"{self.topic}: {self.minutes} minutes"

session = StudySession("Python", 25)
print(session.describe())

Walk through

Create the object, trace the two attributes, then call describe. The result is Python: 25 minutes. Each new instance has its own attributes.

Practice

Create two sessions and print their descriptions. Reject negative minutes in the initializer.

Check yourself

Where does self.minutes live?

Show answer

On the instance referred to by self; it is not automatically shared by every instance.

02Inheritance and magic methods

Understand

Inheritance lets a subclass reuse and extend a base class. Special methods such as __str__ define how objects behave with Python operations; prefer composition when inheritance does not represent a real is-a relationship.

Example

class Task:
    def __init__(self, title):
        self.title = title

    def __str__(self):
        return self.title

class TimedTask(Task):
    def __init__(self, title, minutes):
        super().__init__(title)
        self.minutes = minutes

    def __str__(self):
        return f"{super().__str__()} ({self.minutes} min)"

print(TimedTask("Read", 20))

Walk through

super().__init__ initializes the inherited title. print calls the overridden __str__, which includes the base string and duration.

Practice

Add a method that returns hours as a number; test zero and a positive duration.

Check yourself

What invokes __str__ here?

Show answer

print converts the object to text using its __str__ method.

03Decorators

Understand

A decorator accepts a callable and returns a replacement callable. functools.wraps preserves useful metadata; decorators run when the function definition is evaluated.

Example

from functools import wraps

def trace(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("Calling", func.__name__)
        return func(*args, **kwargs)
    return wrapper

@trace
def add(a, b):
    return a + b

print(add(2, 3))

Walk through

@trace is equivalent to rebinding add to trace(add). The wrapper prints a message, forwards the arguments and returns 5. Avoid logging sensitive arguments.

Practice

Write a decorator that prints Done after a successful function call, and make sure it returns the original result.

Check yourself

Why return func(*args, **kwargs)?

Show answer

It forwards the wrapped function’s result to the caller instead of discarding it.

04Generators and lazy iteration

Understand

A generator produces values on demand with yield. It preserves local state between iterations, which can avoid building a large list, but an exhausted generator cannot simply be reused.

Example

def study_blocks(count):
    for number in range(1, count + 1):
        yield f"Block {number}"

blocks = study_blocks(2)
for block in blocks:
    print(block)

Walk through

Calling study_blocks creates a generator; the loop requests values one at a time. It prints Block 1 and Block 2. Iteration stops when the function ends.

Practice

Change the function to yield a pair of block number and minutes, then test count 0.

Check yourself

What happens when the generator is exhausted?

Show answer

Further iteration produces no values; create a new generator if you need another pass.

05Context managers

Understand

A with statement manages a resource and runs cleanup when the block exits, including on exceptions. contextmanager allows a generator with a yield to define setup and cleanup.

Example

from contextlib import contextmanager

@contextmanager
def session():
    print("start")
    try:
        yield "ready"
    finally:
        print("cleanup")

with session() as state:
    print(state)

Walk through

The output is start, ready, cleanup. The finally block runs on normal exit and when an exception escapes the with block.

Practice

Raise an exception inside the block and confirm cleanup still occurs; then remove the test exception.

Check yourself

Why use finally for cleanup?

Show answer

It runs when control leaves the block, even if an exception occurs.

06Async and await

Understand

Asyncio schedules cooperative tasks: await yields control while an awaitable is pending. It is useful for concurrent I/O, but CPU-heavy work still blocks the event loop unless moved elsewhere.

Example

import asyncio

async def task(name):
    await asyncio.sleep(0.01)
    return f"Done: {name}"

async def main():
    results = await asyncio.gather(task("A"), task("B"))
    print(results)

if __name__ == "__main__":
    asyncio.run(main())

Walk through

gather schedules both coroutines and returns their results in input order. sleep demonstrates a nonblocking wait, not a network request. asyncio.run belongs at the program boundary.

Practice

Add a third task and compare gather with awaiting tasks one at a time.

Check yourself

Does async automatically make CPU-bound code parallel?

Show answer

No. CPU-heavy code can block the event loop; use an appropriate executor or process.

08Files, JSON and CSV

Understand

Use explicit UTF-8 text encoding and with blocks to close files. JSON represents structured data, while CSV stores rows. Validate data from untrusted sources and never deserialize untrusted pickle data.

Example

import csv
import json
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    root = Path(folder)
    (root / "task.json").write_text(json.dumps({"done": False}), encoding="utf-8")
    with (root / "tasks.csv").open("w", encoding="utf-8", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=["title", "minutes"])
        writer.writeheader()
        writer.writerow({"title": "Read", "minutes": 20})
    print(json.loads((root / "task.json").read_text(encoding="utf-8")))
    with (root / "tasks.csv").open(encoding="utf-8", newline="") as f:
        print(list(csv.DictReader(f)))

Walk through

TemporaryDirectory removes its test files at exit. DictReader returns strings for CSV fields, so convert and validate numeric values explicitly.

Practice

Read the minutes field as an integer and handle a missing or invalid value.

Check yourself

Does CSV automatically preserve Python integer types?

Show answer

No. CSV fields are text; parse and validate types when reading.

01FastAPI: request and validation

Understand

FastAPI uses Python types and Pydantic models to validate request data. A request is untrusted; validate values and return appropriate status codes.

from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class Task(BaseModel):
    title: str = Field(min_length=1, max_length=100)

@app.post("/tasks", status_code=201)
def create_task(task: Task):
    return {"title": task.title}

Walk through

Save as main.py, install fastapi and uvicorn in a virtual environment, then run uvicorn main:app. POST a JSON title. This example echoes data; it does not persist it.

Practice

Add a bounded minutes field and test a valid request and an invalid request.

Check yourself

What happens to an empty title?

Show answer

Validation rejects it before the handler processes the request.

03SQLAlchemy: transactions and persistence

Understand

SQLAlchemy maps Python objects to database rows. Sessions manage units of work; commit saves changes and rollback discards an unsuccessful transaction.

Example

from sqlalchemy import create_engine, Integer, String
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, Session

class Base(DeclarativeBase):
    pass

class Task(Base):
    __tablename__ = "tasks"
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    title: Mapped[str] = mapped_column(String(100))

engine = create_engine("sqlite:///:memory:")
Base.metadata.create_all(engine)
with Session(engine) as session:
    session.add(Task(title="Read"))
    session.commit()
    print(session.query(Task).first().title)

Walk through

The in-memory database disappears when the process exits. The example prints Read. Production systems need migrations, persistent storage and connection management.

Practice

Insert a second task and query both; test what happens if you roll back before committing.

Check yourself

Why will these rows disappear after the program ends?

Show answer

sqlite:///:memory: uses a process-local in-memory database.

04JWT authentication: verification boundaries

Understand

A signed JWT can carry claims, but a signature is not encryption. Validate allowed algorithms, signature, expiry, issuer and audience; authenticate and authorize separately. Never place passwords or secrets in a token.

Example

import os
import jwt

def verify_token(token: str) -> dict:
    return jwt.decode(
        token,
        os.environ["JWT_VERIFY_KEY"],
        algorithms=["RS256"],
        audience="study-api",
        issuer="https://issuer.example",
        options={"require": ["exp", "iat", "iss", "aud", "sub"]},
    )

Walk through

This is a verification function, not an issuer or login system. Install PyJWT with cryptography and supply a trusted public verification key. Catch verification errors at the API boundary and reject invalid tokens.

Practice

Write tests for expired tokens and wrong audience using test keys only. Decide how signing keys will rotate.

Check yourself

Does decoding a JWT without signature verification authenticate a user?

Show answer

No. Claims are untrusted until signature and required claims have been validated.

Advanced C: Memory, Structures & Files

Before you start: C basics, pointers and functions.

Practice setup: Compile examples locally with a C11 compiler and warnings enabled. Use sanitizers where available.

3 lessons
01Dynamic memory ownership

Understand

malloc allocates memory and may fail. Every successful allocation needs one matching free; after free the pointer must not be dereferenced. Check sizes and avoid integer overflow in real allocations.

Example

#include <stdio.h>
#include <stdlib.h>
int main(void) {
    size_t n = 3;
    int *items = malloc(n * sizeof *items);
    if (items == NULL) return 1;
    for (size_t i = 0; i < n; ++i) items[i] = (int)i;
    printf("%d\n", items[2]);
    free(items);
    return 0;
}

Walk through

Compile with cc -std=c11 -Wall -Wextra -Werror. The program prints 2 and releases the allocation. Do not access items after free.

Practice

Use calloc and print three initialized values; use an address sanitizer if your compiler supports it.

Check yourself

What happens if allocated memory is never freed?

Show answer

It leaks until reclaimed by the environment, and repeated leaks can exhaust resources.

02Structures and pointers

Understand

A struct groups related values under one type. The -> operator accesses a member through a pointer; it requires a valid pointer to an object.

Example

#include <stdio.h>
typedef struct { int minutes; const char *topic; } Session;
int main(void) {
    Session s = {25, "C"};
    Session *p = &s;
    printf("%s: %d\n", p->topic, p->minutes);
    return 0;
}

Walk through

s owns its integer field and stores a pointer to a string literal. p points to the live local object. The output is C: 25.

Practice

Add a function accepting const Session * and printing its fields.

Check yourself

What does p->minutes mean?

Show answer

It is shorthand for (*p).minutes.

03File I/O and errors

Understand

File operations can fail. Always check fopen and output results and close an opened stream. Text files and binary formats need explicit conventions for portability.

Example

#include <stdio.h>
int main(void) {
    FILE *file = tmpfile();
    if (!file) return 1;
    if (fputs("study\n", file) == EOF) { fclose(file); return 1; }
    rewind(file);
    char line[32];
    if (fgets(line, sizeof line, file)) printf("%s", line);
    if (fclose(file) == EOF) return 1;
    return 0;
}

Walk through

tmpfile creates a temporary stream; the code writes, rewinds, reads a bounded line and closes it. The printed output is study.

Practice

Handle a read failure explicitly, and explain how to handle lines longer than the buffer.

Check yourself

Why check fopen or tmpfile before using the stream?

Show answer

Opening may fail, so a null FILE pointer must not be used.

3 lessons
01Structs and methods

Understand

Structs group named fields. An impl block defines methods, and &self borrows a value without consuming it.

Example

struct Session { topic: String, minutes: u32 }
impl Session {
    fn describe(&self) -> String {
        format!("{}: {}", self.topic, self.minutes)
    }
}
fn main() {
    let s = Session { topic: String::from("Rust"), minutes: 25 };
    println!("{}", s.describe());
}

Walk through

The method borrows s and formats its fields. It prints Rust: 25; s remains available afterward.

Practice

Add a method returning whether minutes is at least 30.

Check yourself

Why use &self for describe?

Show answer

The method only needs a shared borrow and does not take ownership.

02Traits and generic behavior

Understand

A trait describes shared behavior. Generic bounds allow a function to accept different types that implement the required trait.

Example

trait Describe { fn describe(&self) -> String; }
struct Topic { name: String }
impl Describe for Topic {
    fn describe(&self) -> String { self.name.clone() }
}
fn show<T: Describe>(item: &T) { println!("{}", item.describe()); }
fn main() { show(&Topic { name: String::from("Rust") }); }

Walk through

Topic implements Describe; show accepts a shared reference to any type satisfying that bound. The example prints Rust.

Practice

Implement Describe for a second struct and pass it to show.

Check yourself

What does T: Describe require?

Show answer

The type supplied for T must implement the Describe trait.

03Lifetimes and modules

Understand

Lifetime annotations describe relationships between references; they do not extend a value’s actual lifetime. Modules group related code and control visibility.

Example

mod text {
    pub fn longer<'a>(a: &'a str, b: &'a str) -> &'a str {
        if a.len() >= b.len() { a } else { b }
    }
}
fn main() {
    let first = String::from("rust");
    let second = String::from("go");
    println!("{}", text::longer(&first, &second));
}

Walk through

The returned reference is valid only within the lifetime allowed by both inputs. pub makes longer accessible outside its module. The example prints rust.

Practice

Try an input with a shorter scope and examine the compiler’s lifetime error.

Check yourself

Does a lifetime annotation keep the strings alive?

Show answer

No. It describes a borrowing relationship; the values still follow their actual scopes.

01DOM events and delegation

Understand

Events can bubble from a child to a parent. Delegation lets a parent handle interactions for multiple children, including ones added later. Treat user-supplied text as text, not HTML.

Example

<ul id="tasks"><li><button type="button">Read</button></li></ul>
<p id="status"></p>
<script>
document.querySelector("#tasks").addEventListener("click", (event) => {
  const button = event.target.closest("button");
  if (!button || !event.currentTarget.contains(button)) return;
  document.querySelector("#status").textContent = `Selected: ${button.textContent}`;
});
</script>

Walk through

Place this in a local HTML file and click Read. The parent receives the bubbling click and safely sets textContent. This site’s sandbox may restrict scripts in previews.

Practice

Add another button dynamically and confirm the same parent handler handles it.

Check yourself

Why use textContent rather than innerHTML for an untrusted label?

Show answer

textContent treats the value as text instead of interpreting it as HTML.

02Fetch, async and errors

Understand

fetch rejects for network errors, but HTTP 404 and 500 responses still resolve. Check response.ok, validate expected data and handle cancellation or failure in real applications.

Example

async function loadTasks() {
  try {
    const response = await fetch("/api/tasks");
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const tasks = await response.json();
    console.log(tasks);
  } catch (error) {
    console.error("Could not load tasks", error);
  }
}
loadTasks();

Walk through

This is a client snippet for an application that actually provides /api/tasks; it will not magically create an API. Run it against a same-origin test endpoint.

Practice

Show a loading state and a retry button in a real page, and validate that the returned data is an array.

Check yourself

Does fetch automatically reject an HTTP 404?

Show answer

No. Check response.ok or response.status to handle HTTP errors.

03React state and components

Understand

A React component describes UI from state. Calling a state setter schedules a re-render; when the next value depends on the previous one, use the functional updater.

Example

import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(previous => previous + 1)}>
    Study blocks: {count}
  </button>;
}

Walk through

Put this component in a React project created with a supported build tool. Each click increments count and React updates the button text. JSX requires a build setup.

Practice

Add a reset button and ensure both controls have clear labels.

Check yourself

Why use the functional state updater?

Show answer

It computes the new value from the previous state, avoiding reliance on a stale captured value.

02Git rebase and cherry-pick

Understand

Rebase replays commits onto a new base; cherry-pick applies selected commits. Both can create new commit IDs. Avoid rewriting shared history without coordination.

Example

git rebase main
# Resolve conflicts, then: git add <resolved-file> && git rebase --continue
# If needed: git rebase --abort
# To copy one reviewed commit: git cherry-pick <commit-id>

Walk through

Check that the working tree is clean. Read conflict markers carefully and run tests after resolving them. Replace placeholders with real local names; never paste them blindly.

Practice

Why avoid rebasing a shared branch without agreement?

Show answer

Rewriting published commits can disrupt collaborators and require coordinated recovery.

3 lessons
01A small scikit-learn project

Understand

Split data before fitting, evaluate on held-out examples and avoid leaking test information into training. Small demonstrations are not reliable evidence of real-world model quality.

Example

from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

X, y = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)
model = LogisticRegression(max_iter=300)
model.fit(X_train, y_train)
print("accuracy:", accuracy_score(y_test, model.predict(X_test)))

Walk through

Install scikit-learn in an isolated environment. The model fits on training rows and is scored on held-out rows. Do not tune repeatedly on the same test set and call it independent.

Practice

Add a confusion matrix; explain which classes the model confuses and why the sample is not a deployment evaluation.

Check yourself

Why split before fitting?

Show answer

To evaluate on examples that were not used to fit the model and reduce leakage.
